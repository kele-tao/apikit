# Request signing

apikit implements one signing scheme, versioned as `v1`. It is small enough to
reimplement in any language in an afternoon, and that is the point: the signature is
an interoperability contract, not a proprietary blob.

## Canonical string

The signature is HMAC-SHA256 over the UTF-8 bytes of six fields joined by a single
newline (`\n`), with **no trailing newline**:

| # | Field | Value |
| --- | --- | --- |
| 1 | method | uppercase HTTP method |
| 2 | path | request path, must start with `/`, no query string |
| 3 | query | canonical query string (see below), empty when there is none |
| 4 | body | lowercase hex SHA-256 of the raw request body, empty body = SHA-256 of empty string |
| 5 | timestamp | Unix seconds, decimal |
| 6 | nonce | 8-128 chars from `[A-Za-z0-9_-]` |

The canonical query string is built by form-decoding every `key=value` pair,
sorting the decoded pairs lexicographically (key first, then value), and re-encoding
both sides with percent-encoding for everything outside `A-Za-z0-9-._~`. Repeated keys
keep every value, so `tag=dog&tag=cat` and `tag=cat&tag=dog` produce the same
canonical string, while `tag=dog` and `tag=cat` do not.

## Headers

| Header | Example |
| --- | --- |
| `X-Apikit-Timestamp` | `1764000000` |
| `X-Apikit-Nonce` | `nonce-demo-0001` |
| `X-Apikit-Signature` | `v1=82ab7116...349b` |
| `X-Apikit-Signed-Headers` | `x-apikit-timestamp;x-apikit-nonce` |

## Verification order

1. Reject a request with no signature, timestamp or nonce (`missing_signature` /
   `missing_headers`).
2. Reject a signature that is not `v1=` followed by 64 hex characters (`malformed`).
3. Recompute the canonical string and compare with `hmac.compare_digest`
   (`bad_signature`). The comparison is timing-safe.
4. Reject a timestamp further than `--window` seconds from local time (`expired`).
5. When a replay cache is enabled, reject a nonce that was already accepted
   (`replay`).

Signature comparison happens **before** the timestamp check on purpose: an attacker
should not learn whether a forged request failed because of the clock or because of
the secret.

## Test vectors

`examples/signing_vectors.json` is generated by
`python benchmarks/gen_vectors.py` and verified by
`tests/test_signer.py`. The file records, for seven requests, the method, path,
query, body, timestamp, nonce, the exact canonical string and the expected
signature. If you are implementing a client in another language, make those seven
vectors pass before you write anything else.

Secret used for the vectors: `apikit-demo-secret-2026` (a test value, never a
real one).

## Known limits

* The scheme signs the request target, not the `Host` header or arbitrary headers.
  Add a second signature over the headers you care about if you need them covered.
* The replay cache is in-memory and per-process. A multi-instance deployment needs a
  shared store; apikit deliberately does not ship one.
* Clock skew is not compensated. Run NTP.
